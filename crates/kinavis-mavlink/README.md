# kinavis-mavlink

MAVLink 2 for the [KINAVIS](https://github.com/KINAVIS/kinavis) crates:
frames, checksums and signatures, and the position, attitude and mission
messages of ArduPilot.

```rust
use kinavis_mavlink::{Frame, Heartbeat, Message, MAX_FRAME};

let heartbeat = Heartbeat { mav_type: 10, autopilot: 3, mavlink_version: 3, ..Heartbeat::ZERO };
let mut bytes = [0u8; MAX_FRAME];
let len = Frame::new(255, 190, 0, &Message::Heartbeat(heartbeat)).encode(&mut bytes);
assert_eq!(bytes[0], 0xFD); // MAVLink 2
# let _ = len;
```

- **Frames**: a byte-by-byte deframer for MAVLink 2 and 1, checksum with
  `CRC_EXTRA` checked; MAVLink 2 out, trailing zeros dropped.
- **Messages**, generated by `cargo xtask mavlink` from ArduPilot's dialect:
  `HEARTBEAT`, `GPS_RAW_INT`, `ATTITUDE`, `LOCAL_POSITION_NED`,
  `GLOBAL_POSITION_INT`, `MISSION_ITEM_INT`, `SET_POSITION_TARGET_GLOBAL_INT`,
  `GPS_RTCM_DATA`.
- **Kernel types**: positions with heights on their datum, NED velocities,
  attitude, GNSS fixes; waypoints and targets from positions; RTCM
  corrections in fragments. Units and height datum only: MAVLink is NED like
  the kernel.
- **Signing** (feature `signing`): SHA-256 signatures; SHA-256 is the
  crate's own, checked against FIPS 180-4.

Checked against pymavlink: frames of every message encoded there decode
here and the other way round, signatures included. `no_std`, no allocation.

## Feature flags

- `std` *(default)* — standard library maths in the kernel.
- `libm` — for `no_std` targets: `--no-default-features --features libm`.
- `signing` — message signatures.
